# 每日健身计划（离线单文件网页 App）

一个**零依赖、可完全离线运行**的健身计划 App。填写身高、体重、目标与训练条件，它会生成一份**精确到每一天、可以一直练下去**的训练计划，并支持每日打卡与连续天数统计。

在线访问：https://ynz24522-creator.github.io/fitness-plan/

整个 App 就是一个 `index.html` 文件，不需要安装任何东西，不需要联网，也没有后端和账号体系。

## 为什么是"连续"的计划

大多数计划工具只给你一份固定的动作清单，练完就没了。这个 App 的计划是**无限延续**的：每一天（包括休息日）都有明确安排，训练按周推进、每 4 周为一个中周期，可以一直用下去。

计划以**训练日序数**索引，而不是日历周。这意味着漏练不会打乱计划节奏——今天没练，明天的内容会自动顺延上来，分化顺序不会错位。

## 功能

- **精确到天**：训练日和休息日都有具体安排，休息日给出主动恢复建议
- **训练日自己定**：每周练几天、练周几都能自由选择（1–7 天），也可一键套用推荐排布再微调
- **无限延续**：计划没有终点，第 5 周、第 50 周都有内容
- **四周中周期**：第 1–3 周逐步加量，第 4 周主动减载恢复，进入下一周期整体再提升约 3%
- **按身体数据定制**：BMI 分档决定动作库与冲击量，体重百分比决定起始配重，身高影响动作幅度与替代动作
- **三种训练场地**：居家徒手、居家哑铃、健身房，同一套递进逻辑适配三套动作库
- **自动顺延**：漏练或主动跳过都不改变训练日序号，计划不会中断
- **打卡与连击**：训练日和休息日都能打卡，统计连续打卡天数
- **组间计时器**：内置倒计时，结束时用 WebAudio 合成提示音（不需要音频文件）
- **数据本地保存**：所有记录存在浏览器本地存储里，不上传任何服务器

## 身高体重是怎么影响计划的

身体数据不是用来展示的，它真的参与计划生成：

| 维度 | 计算方式 | 对计划的影响 |
| --- | --- | --- |
| BMI | 体重 ÷ 身高² | 分四档：偏瘦（<18.5）、正常（18.5–23.9）、超重（24–27.9）、肥胖（≥28） |
| 肥胖档 | BMI ≥ 28 | **剔除全部跳跃冲击动作**（开合跳、跳绳、波比跳），替换为快走、原地踏步、臀桥、靠墙静蹲等关节友好方案；减脂日的有氧收尾改为长时间快走 |
| 超重档 | BMI 24–27.9 | 跳跃类替换为低冲击版本，并提示控制膝关节角度 |
| 偏瘦档 | BMI < 18.5 | 减少长时间有氧，侧重力量与增肌，建议加长组间休息 |
| 体重 | 相对体重的负重系数 | 决定哑铃/杠铃/器械的推荐重量，再按经验等级与递进系数缩放 |
| 身高 | 偏矮（<165） | 行程较短，建议在可控范围内多完成 1–2 次补足刺激（增力主项除外） |
| 身高 | 偏高（>180） | 长行程，深蹲/硬拉起始重量下调 10% 并提示用箱式深蹲、架上硬拉；用高位下拉替代引体向上 |

配重还会按场地取整：居家哑铃取最近的 0.5 kg 档位，杠铃取 2.5 kg 档位，并从空杆重量起步。

## 训练参数

分化结构由每周训练天数决定，训练经验只调节组数与动作难度层级。**具体练周几完全由你自己选**，下表里的排布只是「推荐预设」快捷按钮的默认值，选完还能单独开关任意星期：

| 每周天数 | 分化 | 推荐预设 |
| --- | --- | --- |
| 1 天 | 全身综合 | 周三 |
| 2 天 | 全身 A / B | 周一、周四 |
| 3 天 | 全身 A / B / C（新手）或 推 / 拉 / 腿（中级以上） | 周一、周三、周五 |
| 4 天 | 上肢 A、下肢 A、上肢 B、下肢 B | 周一、周二、周四、周五 |
| 5 天 | 推、拉、腿、上肢、下肢 | 周一、周二、周三、周五、周六 |
| 6 天 | 推 A、拉 A、腿 A、推 B、拉 B、腿 B | 周一至周六 |
| 7 天 | 推拉腿两轮 + 恢复日（第 7 天低强度，组数压到 2 组） | 周一至周日 |

训练日序号是按你实际选择的训练日顺序连续编号的，所以无论怎么组合，漏练顺延与四周中周期的递进节奏都不受影响。

次数区间与组间休息由训练目标决定：

| 目标 | 次数 | 组间休息 |
| --- | --- | --- |
| 减脂 | 12–15 次 | 45 秒 |
| 增肌 | 8–12 次 | 75 秒 |
| 塑形 | 10–12 次 | 60 秒 |
| 增力 | 主项 4–6 次 / 辅助 8–10 次 | 120 秒 / 90 秒 |

组数按经验等级与中周期周次递进（例如中级为 3、3、4 组，第 4 周减载回落到 2 组）；徒手动作无法加重量时，改为每两个中周期增加 1 组，最多加 2 组。

## 打卡、连击与顺延

- 训练日打卡记为「完成训练」，休息日打卡记为「完成恢复」，两者都算有效打卡
- 连续自然日都有打卡则连击天数 +1，中断则重新从 1 开始
- 漏练或点击「今天跳过」都不会推进训练日序号，同一份训练内容会等到下一个训练日
- 只有完成打卡后，训练日序号才前进

## 快速开始

### 在线使用

打开 https://ynz24522-creator.github.io/fitness-plan/ 即可，手机上也能直接用。

### 本地使用

下载仓库后直接双击 `index.html` 就能运行。

> **Safari 用户注意**：Safari 会限制 `file://` 页面使用本地存储，导致打卡记录无法保存。此时在仓库目录下执行 `python3 -m http.server 8000`，然后访问 http://localhost:8000/ 即可正常保存。（Chrome、Edge 双击打开通常没有问题。）

## 开发与测试

`index.html` 里的计划引擎写在 `<script id="plan-engine">` 中，是一组不依赖 DOM 的纯函数。测试脚本会把它抽出来在 Node 里直接执行，所以不需要浏览器环境。

```bash
node tests/test-engine.mjs    # 662 项断言：分档边界、自定义训练日、中周期递进、顺延、配重档位…
node tests/smoke-ui.mjs       # 68 项断言：三个页签渲染、星期开关交互、打卡写库、休息日分支、非法输入拦截
```

界面测试用一个最小 DOM 桩执行真实界面脚本（包括解析渲染结果来驱动星期开关与快捷预设），并注入固定时钟（2026-09-11 周五），保证断言不随运行日期变化。

## 数据与隐私

- 所有数据保存在浏览器 `localStorage`（键名 `fitnessPlan.v1.profile` 与 `fitnessPlan.v1.progress`）
- 没有账号、没有后端、没有任何网络请求，页面里不含任何外部链接或追踪脚本
- 清除浏览器数据会同时清除打卡记录，「我的」页签里也有清除按钮
